# KazeSU Telegram bot

Interactive companion bot for [KazeSU](https://github.com/KazeSU/KazeSU), the
kernel-based root solution for GKI devices. It answers from the public GitHub
releases and the [KazeSU website](https://kazesu.github.io) — it never uploads
APKs itself, it links to the official assets.

Chat with it at [@KazeKSU](https://t.me/KazeKSU).

## Commands

| Command | What it does |
| --- | --- |
| `/start`, `/help` | About KazeSU, the command list and project links |
| `/latest` | Newest release with APK download buttons |
| `/latest dev` | Newest `Build Manager` run on `dev` |
| `/download` | Manager APK picker by ABI |
| `/download arm64-v8a` | Direct link for one ABI (`armeabi-v7a`, `x86_64`, `riscv64`, `universal`) |
| `/download ko` | Kernel module (`.ko`) assets from the release |
| `/devices [query]` | Unofficial kernels and supported devices, filtered by device or maintainer |
| `/docs [query]` | Installation, build, FAQ and device guides |
| `/status` | Latest release plus the newest `main` and `dev` CI runs |
| `/changelog` | Release notes of the newest release |
| `/issue` | Bug report, feature request and add-device links |
| `/id` | Chat, topic and user IDs (for `ALLOWED_CHAT_IDS`) |
| `/ping` | Round-trip check |

The command menu is registered in English and Simplified Chinese on startup.

## How it runs

Two modes, selected by `WEBHOOK_URL`:

- **Long polling** (default) — no inbound port, best for a VPS or a small
  always-on box.
- **Webhook** — serves `POST /telegram` and `GET /healthz` on `PORT`. Used by the
  bundled Render blueprint, because Render's free instance sleeps when idle and
  only wakes on inbound HTTP.

Only `TELEGRAM_BOT_TOKEN` is required. `GITHUB_TOKEN` is optional but raises the
GitHub API limit from 60 to 5000 requests per hour and lets `/status` read
workflow runs; a fine-grained token with no scopes is enough.

## Deploy on Render

The repository ships a [blueprint](render.yaml):

1. Open <https://render.com/deploy?repo=https://github.com/KazeSU/telegram-bot>.
2. Set `TELEGRAM_BOT_TOKEN` (from [@BotFather](https://t.me/BotFather)) when
   prompted. `WEBHOOK_SECRET` is generated by Render, `WEBHOOK_URL` comes from
   the service's own `RENDER_EXTERNAL_URL`.
3. Optionally set `GITHUB_TOKEN` and `ALLOWED_CHAT_IDS`.

The free plan sleeps after inactivity; the first message after a nap can take
~30 seconds while the container boots. Render's health check hits `/healthz`.

## Deploy on a VPS (systemd)

```bash
sudo useradd --system --home /opt/kazesu-bot --shell /usr/sbin/nologin kazesu
sudo git clone https://github.com/KazeSU/telegram-bot /opt/kazesu-bot
cd /opt/kazesu-bot
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt

sudo install -m 600 /dev/null /etc/kazesu-bot.env
sudo tee /etc/kazesu-bot.env >/dev/null <<'EOF'
TELEGRAM_BOT_TOKEN=123456:replace-me
GITHUB_TOKEN=
ALLOWED_CHAT_IDS=-1001234567890
EOF

sudo cp kazesu-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now kazesu-bot
journalctl -u kazesu-bot -f
```

Leave `WEBHOOK_URL` empty on a VPS to use long polling.

## Docker

```bash
docker build -t kazesu-bot .
docker run --rm --env-file .env -p 8080:8080 kazesu-bot
```

In webhook mode, publish the port and set `WEBHOOK_URL` to the public HTTPS URL
of the container.

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | — | **Required.** Token from BotFather |
| `GITHUB_TOKEN` | empty | GitHub API token (optional) |
| `WEBHOOK_URL` | empty | Public base URL; enables webhook mode |
| `WEBHOOK_SECRET` | empty | Validated against `X-Telegram-Bot-Api-Secret-Token` |
| `ALLOWED_CHAT_IDS` | empty | Space/comma-separated chat IDs; empty serves everyone |
| `KAZESU_REPO` | `KazeSU/KazeSU` | Repository with releases and CI |
| `KAZESU_SITE_REPO` | `KazeSU/KazeSU.github.io` | Website repo (device requests) |
| `KAZESU_WEBSITE` | `https://kazesu.github.io` | Website base URL |
| `KAZESU_TELEGRAM_URL` | `https://t.me/KazeKSU` | Telegram link in `/start` |
| `KAZESU_DEVICES_URL` | `raw.githubusercontent.com/.../docs/repos.json` | `/devices` data source |
| `PORT` | `8080` | Webhook listen port |
| `LOG_LEVEL` | `INFO` | Python log level |

Copy [`.env.example`](.env.example) to `.env` for local runs.

## Development

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/pytest -q
TELEGRAM_BOT_TOKEN=123:test .venv/bin/python kazesu_bot.py
```

CI runs the same three checks on every push and pull request
([`check.yml`](.github/workflows/check.yml)). Tests cover the text/asset helpers
and handler wiring; nothing contacts Telegram or GitHub.

Layout:

```
kazesu_bot.py          bot, commands, GitHub client, polling/webhook runner
tests/                 pytest suites
render.yaml            Render blueprint
kazesu-bot.service     systemd unit
Dockerfile             python:3.12-slim image
```

## Notes

- The bot reads the **newest non-draft** GitHub release. Normal manager builds
  (per-ABI + universal) and `.ko` modules are on GitHub; the spoofed manager is
  only distributed through the Telegram topics.
- Dev builds are not published as GitHub releases. `/latest dev` points at the
  workflow run; the APKs live in the Telegram dev topic, and GitHub Actions
  artifacts need a signed-in account.
- Nothing is written to disk and no message content is stored; the bot answers
  each command independently.
